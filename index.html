SECTION 3

Sales/Transaction Economic-Nexus Early Warning

Import sales activity and identify states where modeled economic-nexus thresholds are approaching, met, or may have been met historically. Duplicate document numbers in the same ship-to state count as one transaction under this workpaper convention; state law may define a transaction differently, so transaction-count results require source review.

Files are processed in your browser; this app does not upload transaction data to GitHub.
Screening limitation: The simplified template has only document date, document number, customer, ship-to state, sales before tax, and customer type. Therefore taxable-sales-only thresholds, marketplace-facilitator treatment, product taxability, exemption-certificate validity, physical or other nexus, and state-specific legal definitions of a “transaction” may require additional review. A “Review required” result is a prompt for tax review—not an automatic tax determination. A “Below modeled economic-nexus threshold” result means only that the imported data did not meet the modeled economic-nexus test; it is not a conclusion that the business has no nexus or no sales/use-tax obligation in that state.

GitHub publishing workflow
  1. Research and stage changes here.
  2. Review each diff and its official source. A flashing siren/red star means a material requirement change has been detected or staged and still needs attention.
  3. Approve accepted changes, then download state-nexus.json and update-history.json.
  4. Replace the corresponding files in the repository and commit through a pull request or direct reviewed commit.
  5. GitHub Pages deploys the committed version. Local browser edits alone never modify the repository.

Source URLs in the table should point to primary state authority wherever available. Review dates are working-paper metadata and do not necessarily represent a state agency webpage publication date.
