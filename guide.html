2. GitHub setup using only a browser

1

Upload the project at repository root

Open the GitHub repository, choose Add file -> Upload files, and upload the project contents. Keep index.html at the repository root.

nexus/ ├── .github/workflows/deploy.yml ├── .github/workflows/nexus-review.yml ├── assets/ ├── data/state-nexus.json ├── updates/update-history.json ├── index.html └── guide.html
2

Confirm workflow location

GitHub Actions workflow files must be inside .github/workflows/. Do not leave working copies of deploy.yml at repository root.

3

Enable GitHub Pages

Open Settings -> Pages and select GitHub Actions as the publishing source.

4

Commit and watch deployment

A commit to main automatically starts Deploy GitHub Pages. Open Actions and wait for both build and deploy to turn green.

5

Acceptance test

Open the live Pages URL and verify the controls described below. On a Mac use Command + Shift + R if an older version is cached.

Multi-select filters

These five columns support multiple exact criteria: State/Jurisdiction, Review status, Tax regime, Transaction test, and Nexus threshold sales scope. The filter popover keeps the checkbox in a fixed left column and the label aligned on the right. Use the search field inside the popover to narrow long lists.

Within one multi-select filter, values use OR logic. Across different columns, filters use AND logic.

Horizontal scrolling

Use either the top scrollbar or the bottom table scrollbar. They are synchronized so you do not need to scroll vertically just to move left/right.

Excel export

  • Export filtered table to Excel exports only visible rows.
  • Export all states to Excel exports all 51 jurisdictions.

1

Choose research scope

Select Selected states (up to 10), Visible / filtered rows, or All jurisdictions.

2

Select up to 10 states

For selected-state research, click Show state selector. Search and check up to 10 states. Click Hide state selector to reclaim screen space; the selected-state summary remains visible.

3

Build the prompt

Click Build prompt. Use Copy prompt to move it into your approved research process. Use Clear prompt when you want to empty and rebuild the prompt.

4

Research primary authority

Prefer enacted statutes/bills, regulations, official revenue-department notices, FAQs, and agency pages. Verify threshold, transaction test, measurement period, sales scope, sales counted, collection timing, marketplace treatment, effective date, and source URL.

5

Paste JSON and stage

Paste the returned JSON array into Stage proposed changes and click Stage JSON changes. The app creates field-level current/proposed diffs.

6

Review source before approval

Open the cited source on every material proposal. Confirm the rule is enacted/effective and that dates and wording are accurate. The siren/red star means the material change still needs attention.

7

Approve or reject

Approve only supported changes. Rejected proposals do not change the working row.

8

Download and publish

Download state-nexus.json and update-history.json, upload them to the matching GitHub paths, and commit through a reviewed direct commit or Pull Request.

9

Verify live deployment

Wait for Actions to pass, open the live site, filter to the changed states, open the source links, and run an Excel export as the final acceptance test.

Substantive rules audit baseline and v1.3.2 scope review

v1.3.2 scope/UX control. The rules engine retains structured schema-v5 measurement codes/operators and historical-window safeguards. The new measurement-reference smoke test also requires all 51 jurisdictions to produce a mapped method label, determination explanation, and modeled example.

Special audited engines include Minnesota rolling prior 12 months; Illinois and Missouri quarter-end trailing 12 months; Connecticut's September-30 period; New York's immediately preceding four sales-tax quarters; Texas's preceding 12 completed calendar months; Pennsylvania's prior calendar year; and Vermont's any preceding 12-month period. D.C. exactly 200 retail sales and Texas exactly $500,000 are forced to human review where current materials are not uniform at the exact boundary.

The app is an economic-nexus early-warning/watchlist workpaper, not a complete nexus or return filing-frequency engine. A below-modeled-threshold result is not an all-clear because other nexus bases and facts outside the simplified import are not tested. Review current primary authority before starting or stopping registration, collection, remittance, or filing.

Transaction screening in v1.3.2

The app now has a separate Sales/Transaction Economic-Nexus Early Warning section. Download the simplified XLSX/CSV template, populate Document Date, Document #, Customer, Ship-to State, Sales $ Before Taxes, and Customer Type, then import one or more files. Set the actual data coverage dates and analysis date. The app applies each state's stored measurement period, counts each state/document number once for transaction screening, flags incomplete-period data, and identifies Review/Watch/Below-modeled-threshold states. Below-modeled-threshold is based only on imported data and is not a no-nexus conclusion. Use the state primary-source link before deciding registration, collection, or filing timing.

Click the information icon beside any Measurement Period to see the modeled date window and an operational explanation, including current/prior-calendar-year and quarter-end examples.

7. Governance reminder

Research does not equal publication. AI/research output should be staged, compared to the current record, checked against primary authority, approved by a qualified reviewer, and then committed to GitHub. Do not bypass a failed validation merely to publish.
